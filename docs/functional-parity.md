# Перенос функциональности legacy-версии

Этот документ фиксирует согласованные продуктовые правила и служит проверяемой
матрицей функционального паритета. Legacy-код удаляется только после завершения
всех обязательных пунктов и сквозной приёмки.

## Зафиксированные правила

- Категории персонажей: только `Игрок`, `NPC`, `Враг`.
- Мысли опубликованного хода видят и слышат зрители. Другие модели-персонажи их
  не получают; собственные прошлые мысли доступны исходной модели.
- AI сначала создаёт редактируемый GM-черновик мысли и действия. В игровой лог
  ход попадает только после подтверждения GM.
- GM выбирает способ публикации хода: без кубика или с серверным d20.
- Единый выбор персонажа синхронно управляет GM-карточкой, зрительской сценой и
  участием в текущем событии. Карта и музыка управляются с верхней панели.
- Редактор перемещения аватаров временно удалён до согласования новой механики.
  Spectator получает сохранённое состояние только для чтения.
- У персонажа есть отдельные portrait и full-body avatar. Дополнительные позы
  в первую версию не входят.
- Хроника принадлежит персонажу, а не кампании. После завершения игрового
  события Архивариус объединяет хроники только его участников и записывает
  согласованный результат каждому из них.
- Персональные заметки после события создаются только для участников категории
  `Игрок`, как в legacy-логике.
- Добавление и удаление означает только включение персонажа в сцену. CRUD
  персонажей кампании пока не входит в объём работ.

## Матрица

| Возможность | Статус | Примечание |
|---|---|---|
| Выбор реальной кампании | готово | Активная кампания сохраняется в SQLite |
| Игровое событие и отдельный текущий лог | готово | Двухфазное завершение не очищает текущий лог до атомарного сохранения памяти |
| Участники события | готово | Синхронизируются с выбором персонажей; участник с опубликованным ходом сохраняется для Архивариуса |
| Категории Игрок/NPC/Враг | готово | Legacy-роли нормализуются при миграции |
| Выбор локации | готово | Нормализованная модель, API, GM UI, spectator |
| Выбор/старт/стоп/громкость музыки | готово | С browser audio unlock на spectator |
| Добавление/удаление персонажей на сцену | готово | Персонаж не удаляется из кампании |
| GM-позиционирование аватаров | отложено | Старый редактор удалён; серверные координаты сохранены до проектирования новой механики |
| Портрет + полноразмерный аватар | готово | Legacy importer и sync поддерживают оба слота |
| Публичные мысли зрителям | готово | Private memory по-прежнему закрыта |
| Опциональный d20 | готово | «Отправить» публикует без кубика, «Отправить с dice roll» запрашивает серверный d20 |
| AI-черновик до публикации | готово | LLM job не изменяет лог, GM редактирует и публикует |
| Богатый prompt игрока | частично | Добавлены stats, inventory, effects, участники и собственные мысли |
| Выбор и нижняя лента GM-карточек | готово | Один список управляет карточкой, spectator-сценой и участием в событии |
| Редакторы GM-карточек | частично | Legacy-паритет готов: HP/MP, просмотр характеристик, inventory и status effects; редактирование характеристик и biography остаётся отдельным расширением |
| Автоматический Observer и редактор typed operations | частично | Backend готов; UI пока покрывает только ручной HP-сценарий |
| Карточки и модальные сведения spectator | частично | Краткие карточки готовы, подробная модаль ещё не перенесена |
| STT в GM Console | не готово | Защищённый backend job готов, UI записи ещё не подключён |
| TTS thought/action и управляемое воспроизведение | не готово | Требуется отдельный worker и очередь playback |
| Archivist: хроники, private notes, атомарная финализация | готово | LLM-черновик редактируется GM; при сбое доступны повтор и ручной результат без потери лога |
| Сжатие длинного контекста | не готово | Будет отдельной идемпотентной Archivist job |
| Полный Playwright игровой цикл | частично | Покрыты ход, Observer, spectator и ручное завершение после отказа Архивариуса; voice ещё не подключён |

## Следующий обязательный срез

1. Расширить GM-карточки редактированием характеристик и biography.
2. Автоматический Observer с редактируемыми типизированными операциями.
3. STT/TTS и последовательное spectator-воспроизведение по `turn_id`.
4. Сквозная приёмка и удаление legacy-кода после подтверждённого паритета.

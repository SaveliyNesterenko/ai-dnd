# Contributing

1. Создайте небольшую ветку с префиксом `feat/`, `fix/` или `docs/`.
2. Не добавляйте реальные кампании, prompts, ключи, голоса или media без
   подтверждённой лицензии.
3. Выполните backend и frontend checks из README.
4. Добавьте миграцию для каждого изменения schema.
5. Для изменяющего API опишите idempotency и optimistic concurrency.
6. Используйте Conventional Commits и заполните PR checklist.

Архитектурные решения, меняющие границы слоёв или source of truth, оформляются
ADR до реализации.
